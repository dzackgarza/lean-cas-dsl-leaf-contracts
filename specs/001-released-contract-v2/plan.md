**Branch**: see "Source location" | **Date**: 2026-11-25 | **Spec**: [spec.md](spec.md)

## Summary

Release `cas-computation/2` with its SDK and a generated category-indexed interface. The
protocol-2 material exists on `integration/kernel-v1-20261106` (revision `a0417b0`) and in an
unpublished local worktree. This plan publishes it, completes every frame and rule that the
kernel tasks consume, adds the generated category view with structural flags, removes legacy
and route rules from the public documents, adds contract tests with a real leaf process and a
real protocol peer, releases `v2.0.0` at kernel F, and merges the result into `main` as
`v2.0.1` at kernel T105.

## Technical Context

**Language/Version**: Lean 4 (`CasContract`, `peer/Driver.lean`); Python 3.12 or later (SDK).
**Toolchain pins**: the integration branch builds on Lean `v4.33.0` and the Mathlib of the
kernel branch; `main` builds on the toolchain of the research image (`lean-toolchain` at
`ef3771d`: `leanprover/lean4:v4.36.0-rc2`, lean-categories main lock), and follows the image
(FR-026).
**Primary Dependencies**: lean-categories (catalogue rows read by the exporter); `pydantic`
(SDK frame models, locked in `uv.lock`); `pytest` (contract tests, dev dependency).
**Storage**: committed files only: generated `api/*.json`, `tests/logs/`, `tests/timing/`.
**Testing**: `just test` (tier 1, `uv run --frozen pytest tests/contract`), after
`just setup` (`uv sync --frozen`, `lake build cas-peer`).
**Target Platform**: Linux in the research container (constitution RC16).
**Project Type**: library and wire contract.
**Performance Goals**: tier 1 under five minutes after setup (SC-001).
**Constraints**: no kernel source in any published file (RC9); generated files never edited by
hand (RC3).
**Scale/Scope**: the frames of FR-001 to FR-013; the catalogue of the pinned lean-categories
revision.

## Source location

The kernel branch `integration/kernel-v1-20261106` of lean-cas-dsl builds on Lean `v4.33.0` and
locks this repository at `a0417b0` of the branch of the same name. The kernel tasks that consume
this feature (T017–T023, T027, T028, T042, T061, T100, T101, T113, T302, T322) run on that kernel branch before its port
to the research image (kernel issue #90, completed at kernel T352). Source: kernel `AGENTS.md`,
"Source location"; kernel `tasks.md`, T105.

Decision: the contract work of tasks T003–T018 and T021 is committed on
`integration/kernel-v1-20261106` of this repository, which the kernel branch consumes. The
governing documents (constitution, `AGENTS.md`, `README.md`, `CONTRIBUTING.md`, `specs/`) are
the same on both branches; an edit to one is committed on both. Task T019 releases `v2.0.0` on
that branch at kernel F, after kernel T100 and T101, as the release of the publication of kernel
T028, for the leaf work of the computational milestones, the kernel category tasks. Task T020 merges
the branch into `main` on the toolchain of `main` with the kernel port of #90 (kernel T352) and
releases `v2.0.1` on `main`, the delivery release. Source: the kernel rule that both kernel branches carry the same governing
documents; the delivery-inputs policy (latest main at delivery).

`CasContract.Port`. A scenario file lists the frames that the driver sends and the frames or
outcomes that it expects. Neither peer computes mathematics; scenario values are opaque JSON.

## Merge and release

1. T001 publishes `a0417b0` and the local worktree changes on the integration branch; T022
   moves `main` to the Mathlib revision and toolchain of the research image (FR-026).
2. T003–T018 and T021 land on the integration branch; the kernel branch consumes each revision.
3. T019, at kernel F: `just export-api` against the built kernel branch, the unchanged output
   committed, `pyproject.toml` version `2.0.0`, tag `v2.0.0`. The kernel branch pins it.
4. T020, after kernel T352 and before kernel T105: merge into `main`; `lean-toolchain` and
   lean-categories take the values of `main`; `lake update` regenerates `lake-manifest.json`;
   every module builds; tier 1 passes; `just export-api` against the ported kernel; tag `v2.0.1`.
   Pull request #11 is the record of this merge. Kernel T105 pins `v2.0.1` in kernel `main`.
